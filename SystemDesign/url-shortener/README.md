# URL Shortener: Scope and Request Flow

This is the system design block after Two Sum in Day 1 of the 60-day plan. The exercise is to write three functional requirements, two non-goals, and one measurable latency goal, then draw client → API → database.

| File | Purpose |
| --- | --- |
| [practice.md](practice.md) | Your own design, assumptions, diagrams, and explanation. Fill in the TODOs. |
| [reference.md](reference.md) | A completed example to compare with your reasoning. |
| [Shared explanation](../../Explanation/url-shortener.md) | A step-by-step tutorial, worked request flows, terminology, and interview follow-ups. |

## What to do

1. Open `practice.md` in your editor and read the prompt.
2. Try the scope and first diagram yourself. Use the guide when you need help.
3. Trace creating a link and opening it. Trace an unknown code and a storage failure too.
4. Explain one trade-off in 60–90 seconds and record whether your attempt was independent or guided.
5. Review the Markdown changes, commit your worksheet, push your branch, and open a PR into `main`.

This exercise produces a design document. The sample API messages describe a proposed service; no server is implemented or running. The latency target is an exercise assumption, not a measured result.
