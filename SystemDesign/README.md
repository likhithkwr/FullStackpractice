# System Design

Practice choosing a system's responsibilities, data, request flow, and trade-offs. A design explains how the parts work together and what happens when a part fails.

## Local practice

1. Read the exercise's prompt and fill in its `practice.md` on your own branch.
2. Study the completed `reference.md` and the shared guide in `Explanation`.
3. Draw the request flows and explain your choices aloud.
4. Record what you needed help with. Revise the design when you can explain the reason for each choice.

Use Markdown in VS Code or another text editor. Markdown preview displays the prose and tables. GitHub renders the Mermaid diagrams used here; local Mermaid rendering depends on your editor's support. These are design documents, so there is no program to run for this exercise.

For the Day 1 session, spend 5 minutes recalling the problem, 15 minutes writing and drawing, and 5 minutes explaining trade-offs. The longer guide is a reference; completing this exercise does not mean completing an entire system design course.
